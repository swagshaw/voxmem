VoxMemBench Does a spoken-dialogue system remember what it heard?

A model is given many time-separated sessions of a conversation — every user turn as audio, every assistant turn as text — and then a spoken question whose answer is somewhere in that history.

Why audio

A text memory benchmark asks whether a model can find the right sentence again. This one asks something a transcript cannot answer. Three of the four evidence types are carried by the audio signal rather than by the words, so a system that transcribes first and remembers later cannot reach them.

The task

What is measured

Four memory operations cross the four evidence types, giving 15 occupied cells. speech_semantics × information_extraction is deliberately empty: reading one fact out of one transcript is not what this benchmark is for.

Memory operationThe item asks the model toItems
information_extractionrecover one fact from one session920
multi_session_reasoningcombine evidence across sessions884
temporal_evolution_trackingtrack how something changed over time872
answer_refusalrecognise that the history does not contain the answer520

Four context lengths, one question

Every question appears at 8K, 16K, 32K and 64K audio tokens under one question_id. Question, gold answer and evidence are identical across the four; only the surrounding history grows, and it nests — sessions(8K) ⊆ sessions(16K) ⊆ sessions(32K) ⊆ sessions(64K) — so a length comparison holds the item fixed and varies only the distraction. The same-key distractors scale 1 / 2 / 4 / 8 with it.

Every user turn ships its transcript alongside its audio, so the benchmark can be read as well as heard and a text-only run gives the ceiling the audio numbers are measured against. The transcript is the words only — the cue markers that drove the delivery are not in it, which is what keeps the paralinguistic, speaker and environmental items out of a reader's reach. Do not put the transcripts in the prompt for a listening run.

Scoring

Accuracy, reported for two strata that are never averaged together. Answers are open ended, so an LLM judge settles equivalence — and it sees only the question, the gold and the response, never the audio and never the history, so it cannot answer the item itself.

StratumItemsCorrect when
answerable2,676the response means the same as the gold answer
answer_refusal520the response says the evidence is insufficient

Report per context length and per cell as well. The aggregate hides that the audio-only cells behave nothing like the semantic ones — which is the point of the benchmark. 

# runner and scorer
git clone https://github.com/swagshaw/voxmem && cd voxmem
pip install -r requirements.txt

python run_voxmembench.py --config 32k --model gemini:gemini-2.5-flash \
    --allow-abstention --out predictions_32k.jsonl
python score_voxmembench.py --predictions predictions_32k.jsonl \
    --judge openai:gpt-4o-mini

Local models plug in through a one-function adapter; a Slurm job-array submitter and a resumable matrix runner ship with the code.

How the data was made

User speech is synthetic, voice-cloned from 30 reference speakers of the CSTR VCTK Corpus; the persona profiles are fictional and are not recoverable from the voice. Assistant turns are text and were never spoken. Environmental sound comes from ESC-50, mixed into the user speech at a target SNR rather than appended, so it is present while the user talks. Paralinguistic cues are rendered as vocal delivery in the cloned speech. All audio is 24 kHz mono.

Gold answers, evidence-session annotations and evidence positions are all public. There is no hidden split and no submission server: the benchmark is meant to be run locally and analysed.
